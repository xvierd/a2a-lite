# Auditoría de interoperabilidad de A2A Lite

**20 de noviembre de 2026 · Python, TypeScript y Java ·** [main auditado, `eb2ebc9`](https://github.com/xvierd/a2a-lite/commit/eb2ebc9ff4e1bfcca085be9cc504faba8ad214a2). El checkout local y GitHub coincidían. Python y npm declaran Lite 1.2.1 y Java declara Lite 1.2.0. Los experimentos con dependencias nuevas se hicieron fuera del árbol de trabajo.

Las nueve parejas Lite funcionan para el camino que ya cubre el repositorio. Los fallos de mayor impacto aparecen al cambiar una condición común en otros clientes o despliegues. Ocurren cuando un interlocutor devuelve un error durante el stream, publica el endpoint bajo otro path, exige un tenant o envía texto libre a un agente con varias skills. Además, el router público de Java falla al arrancar con la versión de Javalin que indica el proyecto.

La auditoría describe el estado inicial de `eb2ebc9`. Los seis cambios se implementaron para 1.3.0. La [guía de migración](../MIGRATION.md) recoge los cambios de API y la [lista de verificación](todo.md) recoge los resultados.

## Qué se comprobó

La matriz entre lenguajes y la recuperación PostgreSQL figuran en el borrador de workflow. Por eso un fallo de interoperabilidad puede coexistir con un CI verde. ## Fallos reproducidos y pruebas que faltan

| Prioridad | Comportamiento observado | Regresión que debería fallar antes del arreglo |
|---|---|---|
| 1 · Java, router | `AgentRouter.run()` lanza `NoSuchMethodException` al buscar `Javalin.get(String, Handler)` con Javalin 7.2.3. El README lo ofrece en los tres lenguajes. Por inspección, la tarjeta del router anuncia JSON-RPC y REST en la raíz, registra rutas con prefijo y el despacho manual solo reconoce `SendMessage`. El servidor Java standalone sí pasó la matriz. [Router](../packages/java/src/main/java/com/a2alite/AgentRouter.java) · [Matriz publicada](../README.md#feature-matrix) | Arrancar el router real con dos agentes y puertos efímeros. Descubrir la tarjeta y llamar a la URL que publica sin reescribir el path. Probar autenticación por agente, ID de petición, inicio/fin de SSE y lectura de tarea donde se anuncien. |
| 1 · Tres clientes, errores SSE | Un error JSON-RPC por SSE termina como flujo vacío en los tres clientes Lite. Python y TS además descartaron un evento válido repartido entre dos campos `data:` y un error JSON con HTTP 200 antes de empezar el SSE. Ante los mismos bytes, el SDK Python 1.3.1 entregó el texto o lanzó el error tipado. [Python](../packages/python/src/a2a_lite/orchestration.py) · [TS](../packages/typescript/src/orchestration.ts) · [Java](../packages/java/src/main/java/com/a2alite/AgentNetwork.java) | Fixtures de bytes compartidas con error previo, error después de un fragmento, datos multilínea, CR/LF/CRLF, fragmentación UTF-8 y cierre prematuro. Comprobar orden de fragmentos recibidos, código de error, cierre del recurso y fin real del flujo. |
| 1 · Descubrimiento y tenant | Python y TS encuentran JSON-RPC, pero pierden el tenant anunciado. En Java, con REST primero en `/rest` y JSON-RPC segundo en `/rpc`, el registro devolvió `/rest`, la llamada por nombre fue a la raíz y dio 404. Llamar a `/rpc` funcionó. El cliente Java tampoco conserva el tenant de la interfaz. En TS, redescubrir desde `delegate` después de `discover` buscó la tarjeta debajo de `/a2a/rpc` y devolvió 404. [Selección Python](../packages/python/src/a2a_lite/orchestration.py) · [Selección TS](../packages/typescript/src/discovery.ts) · [Delegación TS](../packages/typescript/src/agent.ts) · [Cliente Java](../packages/java/src/main/java/com/a2alite/AgentNetwork.java) · [Regla del protocolo](https://a2a-protocol.org/v1.0.1/specification/#832-client-protocol-selection) | Variar orden de interfaces, versión, path, tenant y tarjeta sin binding compatible. Separar URL de descubrimiento y endpoint. Observar URL/tenant efectivos para envío, consulta, cancelación, suscripción y push, y el aislamiento entre dos llamadas concurrentes. Conservar las restricciones de origen y la rotación de credenciales. |
| 1 · Respuestas JSON-RPC | Python aceptó como resultado vacío una respuesta sin `result` ni `error`. TS aceptó un sobre con versión e ID distintos de la petición. Varios mocks felices omiten esos campos. Los tests actuales comprueban mejor los IDs que emiten los servidores que los que aceptan los clientes. [Extracción Python](../packages/python/src/a2a_lite/orchestration.py) · [Extracción TS](../packages/typescript/src/orchestration.ts) · [Mocks TS](../packages/typescript/tests/orchestration.test.ts) | Separar ID incorrecto, versión incorrecta, ausencia o coexistencia de result/error y error explícito con datos. Validar respuestas de mensajes, tareas y streaming. Usar IDs reales en los casos felices y comparar el resultado con el cliente de referencia. |
| 1 · Actualización Java | `PushNotificationSender.sendNotification` pasó de `void` a `boolean`. El adaptador retorna sin valor en el camino durable y registra fallos por destino. Devolver siempre éxito haría ambiguas las métricas de entrega. [Adaptador local](../packages/java/src/main/java/com/a2alite/server/SdkProtocol.java) · [Contrato oficial](https://github.com/a2aproject/a2a-java/pull/1229) | Comprobar éxito, fallo parcial y total, cero configuraciones y entrega diferida en outbox. Verificar el resultado del sender, el estado del outbox y la reutilización del mismo ID de entrega al reintentar para que el receptor pueda deduplicar. |
| 2 · Integración Google | El helper Lite codifica `{"skill":"greet","params":{"text":"saludo"}}` en una parte de texto. Un ADK que envía una frase normal a la fixture con varias skills recibe el error de selección como texto del agente. Esto afecta la experiencia del consumidor. El protocolo permite que el agente decida el significado del mensaje. [Sonda existente](../tests/interop/official_sdk.py) · [Despacho Python](../packages/python/src/a2a_lite/executor.py) | Cubrir skill única que acepta `message`, agente con varias skills y selección ambigua. Documentar el formato explícito, exponer una ruta de entrada opcional para texto libre y comprobar en ADK tanto el contenido persistido como el estado de error pactado. |

El aviso sobre etiquetas también merece un test de contrato. El JSON recibido de las fixtures Python y TypeScript omite `tags` en la primera skill sin etiquetas explícitas. La tarjeta Java incluye la propiedad. El validador de esquema del TCK aceptó las tres, mientras que el SDK Python nuevo avisó sobre la skill mínima. La especificación declara el campo obligatorio. Probar la tarjeta HTTP publicada tanto con etiquetas explícitas como con los valores del quickstart, y escoger un valor predeterminado que sobreviva a la serialización. [Especificación de AgentSkill](https://a2a-protocol.org/v1.0.1/specification/#445-agentskill) · [Validador del TCK en la revisión examinada](https://github.com/a2aproject/a2a-tck/blob/5e6f37c2d38eb3d7684686243c34d365c83df49b/tests/compatibility/agent_card/test_agent_card.py)

## Cómo repetir las comprobaciones

Para la matriz incluida en el repo, instalar las dependencias de desarrollo de los tres paquetes, ejecutar `./gradlew writeInteropClasspath` desde `packages/java` y usar desde la raíz el comando siguiente. El JSON registra por separado `pairs`, `protocol` y `officialSdk`. [Preparación de fixtures](../tests/interop/README.md)

```sh
python3 tests/interop/run.py --output /tmp/a2alite-interop.json
```

Para repetir el sondeo Google, levantar una de las fixtures `server --port N` de esa guía. En un entorno separado con `google-adk[a2a]==2.15.0` y `a2a-sdk[http-server]==1.3.1`, crear un `RemoteA2aAgent` con la URL completa de la tarjeta y un `httpx.AsyncClient` con la clave de la fixture. Usarlo directamente como agente de un `InMemoryRunner` con una sesión nueva por caso. Ejecutar `run_async` con el saludo explícito, texto plano y la skill `stream`. Comprobar los eventos entregados y recuperar la sesión con `get_session` para contrastar los textos persistidos.

Para el sondeo JavaScript, usar exclusivamente `JsonRpcTransportFactory` o `RestTransportFactory` según el caso al construir `ClientFactory`. Descubrir desde la URL base con `createFromUrl`, autenticar cada operación con `RequestOptions.serviceParameters` y construir los mensajes con `SendMessageRequest.fromJSON`. Verificar el texto del saludo, el ID devuelto por `taskProbe`, el mismo ID en `getTask` y el estado completado al consumir `sendMessageStream`. [API del cliente en el tag probado](https://github.com/a2aproject/a2a-js/tree/v1.3.0/src/client)

Para repetir el subconjunto del TCK, usar la revisión indicada arriba con `uv sync --locked --no-dev` y un intérprete 3.15. Ejecutar desde ese checkout `uv run pytest tests/compatibility/agent_card/test_agent_card.py -m must --sut-host="$AGENT_URL"` una vez por servidor, con `AGENT_URL` apuntando a la raíz HTTP de la fixture.
